## 文档优先级与协作

领域规则以 [transaction-design.md](transaction-design.md) 为准；阶段范围以 [implementation-plan.md](implementation-plan.md) 为准；是否完成以 [acceptance.md](acceptance.md) 和实际证据为准。若与新代码冲突，先检查差异、记录原因并同步规范，不能悄悄删减验收。

AI 领域补充以 [ai-design.md](ai-design.md) 及 [ai-acceptance.md](ai-acceptance.md) 为准；AI 知识种子跟随最新交易契约，尤其是取消后可重买、退款后不可重买的规则。

设计/核验 agent 负责规范、审查与独立复核，实现 agent 负责应用、迁移、脚本和初次自验。阶段完成时附以下清单，避免审查只依赖口头结论：

| 交付项 | 要求 |
| --- | --- |
| 版本 | 完整 SHA；有未提交改动时给出 diff 和状态，避免混合版本结果 |
| 环境 | Windows、JDK、Node、MySQL、Redis、k6 实际版本与机器资源 |
| 复现 | 初始化/迁移、启动、验证、只读对账及非破坏停止命令 |
| 场景 | 关联任务 ID 和验收 ID，分别记录期望、实际、证据 |
| 原始材料 | 测试报告、脱敏响应、k6 输出、SQL/Redis 快照、故障时间线、真实页面演示 |
| 限制 | 未验证项、未决订单、失败窗口、负载瓶颈、暂未实现内容 |

敏感 Token、验证码、完整核销 token 不进入公开报告；仅保留脱敏关联 ID。全部高负载测试使用独立测试活动与账号，数据准备和清理范围明确。
