# CAP-07A2 实际 Feed 公共片段缓存

初版使用版本键 L1/Redis 和一次批量正文 SQL，尚不合并跨 caller 请求。事实目录保留关注、公开状态、版本、门店、本人点赞和游标；窄目录不取正文，RR 事务返回后才借池加载片段与计数。版本缺失或容量拒绝至多一次新 RR 全字段读取，原 cursor/limit 不变；数据库错误明确失败，不写空成功页。

`phase1-related-tests.txt` / `phase1-checks.json` 记录直接相关普通与真实回归。新增真实 HTTP 使用实际登录会话、MySQL/Redis：冷页 1 批 2 行内容 SQL、第二用户热页 0 新内容 SQL；与原全字段事实页相等；单连接无新增池等待；两用户点赞、同秒分页、退关、下架、新版本均核对。内容 SQL 执行前在独立真实连接变更版本/公开状态，恰一次新 RR 回退；实际缺表错误返回 503 且无缓存条目。这些存储层注入不是新增编辑/下架 API。

组件边界测试覆盖版本0/规范payload/坏类型（包括 images:[null]）、独立可变切片、超大合法内容不缓存、双L1预算、Redis故障、等待上限及取消/关闭。内部非作者审查分别覆盖组件、业务路径、生命周期与测试有效性；真实依赖降级/自然过期和跨 caller 合并继续在 A3 验收，不能把组件 stub 测试写成真实依赖成绩。

app 注入同一组件给 Feed 与私有 cards Snapshot，关闭重观测也可见实际内容 SQL 批次/行/字节。资源按 diagnostics→cards→pools 释放，装配失败也关闭组件。hits 只计 caller 首次检查，内部二查不重复计数；公共计数仍使用 CAP-06V 修复和原 TTL。此处无容量成绩，历史秒级长尾仍未知。
