- [冷热缓存](../2026-10-29-go073-cache/report.md)：真实 MySQL/Redis、进程内计数缓存函数。100 次同键冷读回源 100 次；100 次 L1 热读无数据库及 Redis 命令，本机计时结果低于分辨率。20 轮 32 并发冷读共回源 20 次；20 轮每次 32 key 冷批量读取回源 20 次，逐条读取回源 640 次。不是完整 Feed 的 HTTP 性能或生产容量。证据提交 `40fd575`；此次测试在 `bf6b765` 上执行，至 Kafka 修复提交的差异中缓存与 SQL 迁移源码未改，按此边界复用，不冒称在修复后 SHA 重跑。
- [Kafka 首启问题与修复](../2026-10-29-go073-kafka-fix/report.md)：新 broker 上首次建主题时三组可能完成空分配，20 条已投递事件不能投影。修复在后台等待已配置主题和分区可用后才构造消费者，保留组名、提交与位点。专用真实 Kafka 回归覆盖缺主题、自动创建、三组消费、已有位点及取消；随后事件实验以真实 MySQL/outbox/ES 再贯通。失败现场和早期修复尝试保留。修复提交 `45928e6`，CI 覆盖提交 `25f8ecc`；运行期间删除并立即重建同名主题未覆盖。
- [持续交易](../2026-10-29-go073-trade/report.md)：15 秒预热后以 k6 5 次/秒稳定运行 180 秒，901 次稳定请求均唯一受理且逐 ID/用户对应 901 个最终订单，系统错误及 dropped iterations 均为 0；受理耗时 P95/P99 为 31.1233/73.4555 ms。SQL 轮询观察到的响应至首次可见 P95/P99 为 1060/1111 ms，包含约 1 秒的轮询和查询误差；不能当精确提交延迟。预热与稳定共 976 单，MySQL/Redis 库存均为 169、受理映射 976，未决 review 和拒绝事件均 0，PEL 与 group lag 均为 0。本批没有非零拒绝或补偿，补偿恢复沿用 [GO-033 和 GO-070 的已核验范围](../../../STATUS.md)；不能把它们写成持续负载中的新增故障实测。5 次/秒为指定负载而非容量上限。提交 `556c563`。
