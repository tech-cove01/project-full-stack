# CAP-10：一台阿里云 ECS + PTS 的本地准备

用户于2026-11-01确认采用一台ECS部署项目、PTS独立发压，要求先完成本地适配再租机，按小功能提交，原计划测完收尾、不增加轮次。此确认取代此前同机k6或两台ECS的建议。当前无云机、无云调用、无新增业务负载。

此前已说明额外离线适配需约45—75分钟，用户随后明确要求先完成该准备。本次额外离线准备单列，最多75分钟；不重置原有效开发账本、8×60秒短窗、2×180秒正式窗、840秒主负载或最多一项业务优化。云端部署、定位、优化与验收仍接续原剩余预算；等待用户租机不计开发。本机失败与71份原件保持。

PTS官方API没有提供已证完整JTL下载，采样日志不能补完整计数；报告的聚合延迟不能当全样本P95。本批由标准JMeter脚本通过同VPC私网分批回传脱敏原始客户端结果，自行重算全请求和mutation延迟及错误；PTS报告另存辅助展示。收集器不代理业务请求，诊断/数据库继续loopback，不新增应用业务接口。

PTS按500并发/引擎分配时，512个业务线程跨2个引擎，CSV按slot切分，全部512槽位恰好一次认领、实际线程就绪后才发布共同开始时间。每槽计划ordinal=slot+512*j，超过冻结发起抖动预算计drop，不补发。不把512关系池或控制台并发字段当QPS成绩。

本次环境的发压器资源门槛预先分开声明：ECS本地Python收集器与Node分类助手合计仍小于2GiB；两台PTS托管引擎各自进程RSS小于2GiB，逐台CPU连续3次达到85%仍停止，分别记录真实RSS与合计值。原本机k6的合计2GiB限制不用于跨两台独立远端主机相加判OOM。API与四依赖的配额/连接池/持久化保持；任何收益对比只在相同PTS配置下进行，不将换发压器收益算作Go优化。

主窗60/180秒、预热10秒均由客户端原生窗口与收集器完整记录证实。平台任务最短60秒不扩充实际预热；完成后请求停止并确认远端结果/任务收敛。启动失败、云端接线失效、早停或采集失败仍消耗已预约槽位；不额外开云端校准压测。主机就绪后只做必要有限功能准入和一次该环境空载，随后S1=50/s。

正式前必须明确发压器资源、目标资源、时基和全部对账有效；无效提前报告，不先跑正式组。业务性能标准、原候选/搜索算法及停止规则保持，Feed/hot不重跑，旧B1未知和原CAP-09失败不覆盖。
