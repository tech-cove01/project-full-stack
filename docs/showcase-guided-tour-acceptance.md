# 新手引导操作与自验

2026-11-10。范围与用户体验验收状态统一见根 STATUS；本页记录实际操作、证据与限制。复用四场景真实浏览器状态模型，业务后端、压测成绩和原始报告不变。

WEB-010A 先行自验通过后，才开始其余三条。共用引导分为“实际操作”和“看结果”两阶段：监听真实控件事件，先保存操作前快照，在场景处理完成后的冒泡阶段核对操作后状态。只有符合状态条件的动作才能进入结果反馈；“定位”不能替代业务操作。重复请求等不改变事实的保护动作还需要当次真实事件证据。

引导保留当前数据，关闭只恢复自由控件，不重置。重新打开根据当前状态与本页观察到的动作继续；不兼容状态给显式重置入口。刷新仍遵循四场景本来的初始状态，不增加持久化。高级控制只在引导时收起，退出还原。手机提示固定在附近可用区域，短屏使用紧凑滚动气泡。

独立小修：反馈期间收起上一步业务按钮，保留的输入结果暂设 inert，防止重复取消等待者改变正在解释的事实；退出解除限制。输入以 change/“填好了”确认，避免打第一个字即抢走焦点。窄屏入口位于长步骤卡前；长结果面板按气泡与顶栏的实际高度限制为内部滚动区。独立 Chrome 390×440 的交易5步、Feed10步全部完成，15个结果与提示无交叠，退出恢复控件；正常桌面和手机高屏也通过。

## 交易：WEB-010A

从 `demo/?scene=trade` 点击“跟我操作”，或看过欢迎提示后从深链直接开始。

1. 抢券并受理：先高亮真实按钮，再高亮受理 ID，说明库存预占且尚未成单。
2. 看懂后继续，消费成单：高亮当前唯一订单，库存不再次扣减。
3. 重试同一请求，再重复投递：两次均解释为预期保护，原受理、订单和库存保持。
4. 确认消息：持久结果已有，待确认数变为 0。
5. 访客主动选择“取消重买与旧补偿”：取消订单→应用补偿→再次抢券→投递旧补偿。新受理归属保持，库存仍为 4/5，说明旧补偿不能释放新购买。

实际 Chrome 浏览器在 1440×960、390×960 走通主线和分支，16 条操作结果记录（首步另外由截图核对），无脚本异常。检查未操作时反复定位仍停留首步；关闭后高级操作恢复；重开从消费成单继续，库存未清空；重置当前场景明确回到 5/5 并重新引导。记录与首步/反馈截图见 [证据目录](evidence/2026-11-10-guided-tour/)。

独立审查额外发现并修复：已自由完成 ACK 后重开教程可能卡在重复 ACK；曾进入未知状态的旧计划可能一直阻断；欢迎弹窗选择自由体验未停止既有教程；短屏 scroll-margin 与手动偏移叠加导致结果被遮挡。修复后由非作者重新检查实际路径。

## Feed：WEB-010B

从首页第二项进入 `demo/?scene=feed`，看过欢迎弹窗也会直接看到自己的引导，不跳回交易。

读取笔记→完成回源→再次读取热缓存→A点赞→切换B→B读取同一正文但未点赞→清空缓存→发起三个同批冷请求→取消一个等待者→完成回源。每次业务动作后高亮对应正文、个人状态或请求列表，解释结果后才继续。

实际1440×960、390×960完整10步共20条结果通过；每个目标可点击，高亮结果与提示不相交，无横向溢出和脚本异常。完成后关闭重开仍为已完成，重置后从冷读开始，刷新按初始数据开始。独审另重走1440×960、390×844与390×440，各10步通过；取消后只有一条已取消，其余两条已完成，公共缓存不带个人点赞。12项模型与教程测试通过。首步及正文反馈截图和逐步记录见本轮证据目录。

## 搜索：WEB-010C

从第三项进入 `demo/?scene=events`。填写标题并点“填好了”→发布→投递→清空搜索筛选并确认→搜索看到结果→让索引不可用→修改标题并确认→保存新版本→投递失败留停车记录→恢复连接→明确人工重放→重新搜索新版。

实际1440×960、390×960完整12步共24条反馈通过，每步检查实际高亮和结果无遮挡。逐字输入完整标题后才确认，不会输入首字就失去焦点；“填入示例”只填内容，发布仍由访客点击。独审另测空标题确认不推进、非默认关键词的自定义标题、旧版本已投递但新版本尚未投递时重开定位最新投递。索引恢复本身停车数量不变，显式人工重放后停车0、两条收据，新标题能搜到；未静默重置已有事实。12项原模型与教程测试通过，首步与发布反馈截图/逐步结果保留在证据目录。
