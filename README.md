# project-full-stack

一个以黑马点评业务场景为起点，逐步扩展用户端、商家后台和平台管理后台的全栈学习项目。

目标是通过真实业务流程，学习前后端协作、高并发处理与 B 端系统设计，并用测试、压测和故障实验验证实现。

## 业务方向

| 端 | 规划内容 |
| --- | --- |
| 用户端 | 商铺浏览、优惠券抢购、订单查询、到店核销、评价与关注 |
| 商家后台 | 商家与门店管理、员工权限、优惠券活动、库存管理、订单核销、经营报表 |
| 平台管理后台 | 商家入驻审核、内容与活动管理、操作审计、平台数据概览 |

优先打通「商家发布活动 → 用户抢券 → 异步创建订单 → 商家核销 → 报表统计」这条业务链路，再逐步扩展其他功能。

## 学习重点

### 前端

- 用户端与管理后台的路由、状态管理、表单校验和统一接口处理。
- 抢购状态展示、防止重复提交、异步订单结果查询与失败重试体验。
- 列表分页、按需加载、请求取消与缓存，观察页面性能和用户体验。
- 按角色展示功能入口，并与后端权限校验保持一致。

### 后端与高并发

- 缓存穿透、热点缓存重建、缓存与数据库的一致性。
- 库存扣减、订单幂等、数据库唯一约束与事务边界。
- Redis Lua、异步消息、消费确认、重试与失败补偿。
- 限流、超时、线程池容量、消息积压和服务降级。
- 通过指标、日志和压测定位瓶颈，记录优化前后的变化。

### B 端业务

- 商家、门店和员工的数据归属与访问范围。
- 基于角色的权限控制、接口鉴权和操作审计。
- 优惠券活动生命周期、订单状态流转和核销幂等。
- 多商家数据隔离、经营统计和异步导出。

## 实施路线

1. **建立基线**：整理参考实现和配置，准备本地运行环境，跑通商铺、登录与优惠券流程。
2. **补齐正确性**：围绕消息确认、事务、重复下单和写接口权限，建立可复现的测试与修复记录。
3. **实现业务闭环**：完成用户端和商家后台，打通活动发布、抢券、订单查询与核销。
4. **验证并发能力**：加入限流、异步处理和必要的缓存优化，覆盖热点访问与集中抢购场景。
5. **完善运营能力**：补充平台管理、审计、报表、监控和故障恢复实验。

后端先按业务模块组织，随着实际瓶颈与学习需求演进架构。技术选型和部署方式会在实现确定后补充。

## 验证方式

每个阶段同时检查业务结果和系统表现：

- **正确性**：库存不为负、订单不重复、状态流转合法、不同商家的数据隔离有效。
- **性能**：记录吞吐量、P95/P99 延迟、错误率，以及数据库、缓存和消息积压情况。
- **可靠性**：模拟重复消息、消费中断和依赖异常，检查恢复与补偿结果。

压测报告需注明硬件、数据规模、并发模型和配置；当前尚无性能测试结果。
