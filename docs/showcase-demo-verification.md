# 互动演示验收

2026-11-09，WEB-005。基线 `f787173c38d8a2dee0185c443fe82aaf2002bc53`。这是现有项目的静态业务演示，模拟数据不作为后端能力或性能证据。

## 业务链路

- 顾客从街角咖啡/青禾食堂选择优惠。19元购30元咖啡店到店券，或9.90元购20元食堂到店券，均为虚构门店的示例活动。
- 同一状态模型联动库存、受理、成单、模拟支付、凭证、商家核销和记录。处理中不能支付，取消后恢复库存并可重买，退款后恢复库存但保留购买记录、不可重买，核销后不可退款。
- 店员仅授权咖啡店、仅显示本次店员回执；店主可跨两店管理、退款和查看管理审计。错误凭证、重复核销和无门店权限都有可观察反馈。
- 核销后引导探店分享，也允许不购买直接发笔记；支持标题/正文/门店关键词查询与点赞/取消。
- 引导定位下一步操作，支持自由切换视角、刷新恢复当前标签页进度、一键重置。静态演示标识始终可见，浏览器模拟与真实应用设计分明。

## 直接验证

- `node --test scripts/showcase-demo.test.mjs`：8项通过，覆盖受理/防重复、支付核销、取消重买、退款权限/库存/不可重买、核销退款互斥、跨店拒绝、独立发布与期望状态点赞、损坏快照拒绝。
- Chrome + Playwright：1440/768/390像素三种屏幕均走通引导、抢券成单、模拟支付、错误凭证、授权门店、重复核销、店主审计、发布/搜索/点赞、刷新、取消重买、退款和重置。
- 测试将HTML片段作为笔记正文发布，只按文字显示；凭证按文本转义，损坏恢复凭证与计数快照被拒绝。
- 禁用sessionStorage后可按内存模式买券。页面业务操作未发起外部请求，无脚本异常或横向溢出。
- CSS按实际DOM补齐核销凭证输入框、订单标签和值、审计标题；桌面与手机截图检查可读性。
- Go、Vue、数据库、Kafka与既有性能证据未改；不启动后端或云资源，不重跑压测。
