## 交易：WEB-010A

从 `demo/?scene=trade` 点击“跟我操作”，或看过欢迎提示后从深链直接开始。

1. 抢券并受理：先高亮真实按钮，再高亮受理 ID，说明库存预占且尚未成单。
2. 看懂后继续，消费成单：高亮当前唯一订单，库存不再次扣减。
3. 重试同一请求，再重复投递：两次均解释为预期保护，原受理、订单和库存保持。
4. 确认消息：持久结果已有，待确认数变为 0。
5. 访客主动选择“取消重买与旧补偿”：取消订单→应用补偿→再次抢券→投递旧补偿。新受理归属保持，库存仍为 4/5，说明旧补偿不能释放新购买。

实际 Chrome 浏览器在 1440×960、390×960 走通主线和分支，16 条操作结果记录（首步另外由截图核对），无脚本异常。检查未操作时反复定位仍停留首步；关闭后高级操作恢复；重开从消费成单继续，库存未清空；重置当前场景明确回到 5/5 并重新引导。记录与首步/反馈截图见 [证据目录](evidence/2026-11-10-guided-tour/)。

独立审查额外发现并修复：已自由完成 ACK 后重开教程可能卡在重复 ACK；曾进入未知状态的旧计划可能一直阻断；欢迎弹窗选择自由体验未停止既有教程；短屏 scroll-margin 与手动偏移叠加导致结果被遮挡。修复后由非作者重新检查实际路径。
