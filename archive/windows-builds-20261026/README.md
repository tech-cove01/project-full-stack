# 历史 Windows 构建归档（R1）

这里保存原先已被 Git 跟踪的 14 个 `backend/bin/*.exe`，保留原文件名和全部字节。目录日期是历史材料的分类名，不代表每个文件的构建日期，也不代表它们来自同一源码或都已验收。

[manifest.json](manifest.json) 记录每件文件的旧路径、新路径、字节数、SHA256 和原 Git blob。历史报告中的 `backend/bin/` 或更早的 `backend-go/bin/` 路径继续保留原文；核查旧构建时按文件名和 SHA256 查找本目录，不改写旧证据。

这些程序仅供历史溯源，不推荐运行，也不作为当前 API、部署或容量结果。当前 Go 应用从 `backend/cmd/api` 构建；在 `backend/` 执行 `go build -trimpath -o bin/api.exe ./cmd/api` 的输出约定保持不变，构建会在原位置生成新文件。当前操作方式见[运行说明](../../docs/development.md#go-迁移环境与启动)。

本次仅移动清单中的已跟踪文件，不迁移 `backend/bin/` 下被忽略的本地构建、脚本或日志，不修改 Go、SQL、配置及现行 CAP-10 工具。历史文件未删除，Git 历史未重写；移动到 `archive/` 不会缩小 Git 历史或仓库下载体积。

归档前核对了运行脚本、CI、开发说明和历史报告中的引用；当前开发说明使用的是先构建、后运行的 `bin/api.exe`，历史报告保留当时路径。归档后逐件核对 SHA256、字节数及 Git blob；需要取回旧版本时，先按清单验证，再复制到单独的历史核验目录，不覆盖当前构建。
